# Підтримка неділі: compatibility release

## Проблема та реалізація

Сервер примусово відхиляв відкриту неділю, хоча спільна логіка слотів і business opening hours вже підтримує всі сім днів. Такий код не може безпечно читати запланований новий графік після його застосування.

Прибрано лише дві жорсткі заборони неділі: у валідаторі графіка та перерв. Вихідні визначає `closedWeekdays`; відкрита неділя використовує `weekdayHours`. Валідація закритих днів, перерв, суботи й timezone збережена.

## Міграція та rollback

Міграції, реєстрації міграцій, зміни CMS global і schema відсутні. Чинний графік залишається 60 хвилин, неділя/понеділок закриті. Terms, футер, адмінський label та роботи над кешуванням не входять у PR.

До зміни графіка цей PR можна відкотити кодом. Після відкриття неділі відкат старої валідації заборонений без окремо погодженого відновлення сумісного графіка: старий код не прочитає відкриту неділю. Наявні appointments не скорочувати й не скасовувати.

## Ручна перевірка після deploy

1. Відкрити `/book-a-fitting` на mobile/desktop: чинний графік, тривалість і недоступні дні не повинні змінитися.
2. Перевірити `/contact` та openingHoursSpecification головної: поточні години незмінені.
3. Не відкривати неділю в CMS і не запускати міграцію нового графіка в межах цього PR.
4. Лише після успішного Production deployment готувати окремий PR нового графіка.

## Security/privacy, accessibility, SEO/cache

Не додаються запити до appointments, логування, персональні дані, зміни Stripe або consent. Backend залишається авторитетним. Інтерфейс не змінюється, тому скріншоти не застосовні. Доступність, metadata, canonical, приватні headers, кеш-ключі та revalidation hook не змінені. Фактичне відображення неділі залежатиме від наступної погодженої зміни CMS.
